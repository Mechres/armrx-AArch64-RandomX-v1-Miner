### Next Up

2. **W4 phase-2 — dedicated superscalar C* literal pool: SOLVED (2026-08-02).** The active optimization lead is resolved. The reference's dense literal-pool for C* immediates is implemented as a **dedicated per-program PC-relative LDR pool** (not the NEON vector-lane pool — that variant scattered ~714 loads and thrashed cache, −16% to −20% H/s, which is why phase-1/ W3 closed as a regression). The PC-relative inline pool passes the full device gate set (equivalence 16/16 + 2way + determinism + scheduler stress ×2) with no hashrate regression (pooled 4.32 vs baseline 4.27 H/s, 1 worker). Root cause of the prior 15+ failures: a spurious `-8` in the LDR offset (A64 `target = k + off*4`, no `+8`) masked by a circular self-check; Luna's sign-extend fix also required. Instruction-count gap to reference narrowed (C* sites 2–3→1 instr) but the on-order A53 makes it latency-neutral — no further throughput expected from this lever. Remaining gap to reference (104.8M) is now mostly elsewhere (see W1-4 census). See `changelogs.md` (2026-08-02) and `docs/briefs/w4-phase2-investigation-notes.md`.
