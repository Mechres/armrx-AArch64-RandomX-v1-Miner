## 2026-08-01
- **Track G — NEON T-table AES enabled by default:** Flipped `ARMRX_ENABLE_NEON_TTABLE_AES` from OFF to ON in CMakeLists.txt. Code already implemented and KAT-verified (10,000-trial parity test, +28.8% AES throughput microbenchmark). Projected ~3.6% hashrate gain. See `docs/audits/combined-audit-20260731.md` (T0-1). (`CMakeLists.txt`)
- **isolcpus-aware worker pinning (T2-3):** Worker threads now pin exclusively to isolated cores when `isolcpus=` is active. `detect_core_order()` applies an isolation filter (`filter_to_isolated`) on ALL return paths — including the cpufreq-less fallback that previously returned the raw sequential order (verified bug on MSM8929: worker 0 stole housekeeping core 0, core 7 left idle). Default worker count also capped to isolated-core count (`cli_parser.cpp`). On-device verification: `isolcpus detected — workers pinned to isolated cores: 1, 2, 3, 4, 5, 6, 7`, main thread on core 0, all 7 workers on cores 1-7. See `docs/audits/combined-audit-20260731.md` (T2-3). (`src/mining_engine.cpp`, `src/cli_parser.cpp`, `src/cpu_features.cpp`, `include/armrx/cpu_features.hpp`)
- **T1-2 — `--perf-ready` hook (implemented, device verification blocked):** `bench_armrx --full-hash-only --perf-ready` prints `PERF_READY` after warmup/cache-init and gates the measured loop on a stdin line, so `perf stat -p <pid>` captures ONLY steady state (closes the master-plan 2.77× instructions/hash measurement pitfall). Plus `tools/perf_ready_bench.sh` wrapper (fifo + perf attach; fifo deadlock fixed via `<>` open). Host-verified: EOF path, 2s-timeout path, error path, 8/8 ctest. Device verification BLOCKED by a pre-existing JIT-execution hang on device (see below). (`tests/bench_armrx.cpp`, `tools/perf_ready_bench.sh`)
- **KNOWN ISSUE — device JIT execution hangs (regression window identified, root cause pending):** `test_jit_equivalence`, `test_mining`, `bench_armrx --full-hash-only`, and `armrx --mine` all hang (100% CPU spin, zero hashes) on device in JIT-compiled code. Host cannot catch it (x86_64 has no JIT). perf profile: spin in first ~0x340 bytes of JIT buffer, CBRANCH loop region (`b.ne exit; b loopstart`). Track G excluded (test_mining hung on the D2 build with Track G OFF). Regression window: `4794890` (Track B Gate B — last known device-working) → `a683701` (D2); candidates `c7c1b5c` (Track C Phase A prologue — first attempt hung on-device per audit T3-1) and `a683701` (D2). Bisect pending.
